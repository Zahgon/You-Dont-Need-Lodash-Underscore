--------------------------------------------------------------------------------
FACTS ESTABLISHED FOR THE TRANSLATION
--------------------------------------------------------------------------------

1. `lib/rules/rules.json` contains 73 entries, producing 73 distinct rule
   names. There are no rule-name collisions, so no last-write-wins behavior
   needs to be reproduced.

2. The `kebab-case@1.0.0` algorithm is a plain per-character transform: each
   uppercase Latin letter is replaced by "-" + its lowercase form. It does NOT
   understand acronyms. Verified against the real dependency:
       isNaN        -> is-na-n
       forEach      -> for-each
       lastIndexOf  -> last-index-of
       isArray      -> is-array
       startsWith   -> starts-with
       endsWith     -> ends-with
   This is precisely why `rules.json` carries explicit `ruleName` overrides for
   bind, isInteger, isNaN, isNil, isNull, isUndefined, startsWith and endsWith:
   without them `isNaN` would become `is-na-n`. The Go port must reproduce the
   naive algorithm exactly, including the `is-na-n` shape, because rules lacking
   an override depend on it.

3. `tests/unit/all.js` does not exercise the plugin. It asserts that the lodash
   library and hand-written native JavaScript snippets agree. Its subject matter
   is the JavaScript language and the lodash library themselves.
